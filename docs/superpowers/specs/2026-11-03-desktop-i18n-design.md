# Desktop UI 多言語化 設計

## 目的

Vyline Desktop の操作ラベル、設定、入力案内、通知、ダイアログなどの UI 文言を i18n 経由にし、利用者が表示言語を変更できるようにする。LINE から受け取ったメッセージ本文、プロフィール名、公式アカウントの文面など、利用者コンテンツは翻訳しない。

## 方針

- React 連携には i18next / react-i18next を使い、翻訳資源はアプリに同梱する。
- 日本語を常時フォールバック言語にする。未翻訳キーは空欄やキー名でなく日本語を表示する。
- 設定は IndexedDB に保存し、`system` と手動選択を提供する。
- 初期対応ロケール: `ja`, `en`, `zh-TW`, `zh-CN`, `id`, `ko`, `es`, `fr`, `de`, `pt-BR`, `vi`, `th`。
- カタログは必要時に読み込み、起動時に未選択言語を一括ロードしない。
- `Intl` を使って日付・数値・相対時間を現在のロケールで表示する。
- `document.documentElement.lang` を有効ロケールに同期し、言語切替でチャット・スクロール位置・入力途中の文を失わない。
- UI 文言だけを翻訳し、LINE プロトコル値・API payload・永続データ・ユーザー生成コンテンツは翻訳対象にしない。

## 受け入れ条件

1. 日本語、英語、繁体字中国語（台湾）を含む対応言語を設定から選べ、再起動後も選択が残る。
2. system 設定はブラウザーの優先言語から対応ロケールを選ぶ。
3. 未翻訳文言は日本語で表示される。
4. 選択言語の切替で入力中メッセージ・選択中チャット・スクロール位置を保持する。
5. 表示言語は設定バックアップに含め、旧バックアップのインポートでは日本語設定を適用する。
6. 見切れや横スクロールを増やさない。長い翻訳文は既存の可変レイアウトで折り返す。
7. 対応言語、翻訳追加手順、フォールバック仕様を日本語・英語 docs と AGENTS.md に記載する。

## 実装判断

ローカル UI 設定として IndexedDB に保存する。サーバーや LINE へ言語選択を送らない。日本語の既存挙動をベースにし、翻訳キーの欠落を安全に扱う。翻訳対象外の会話データに i18n 関数を通さない。
