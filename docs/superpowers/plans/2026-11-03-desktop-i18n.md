# Vyline Desktop i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Localize all user-facing Vyline Desktop UI strings, add a persistent language selector, and retain Japanese fallback.

**Architecture:** Use i18next with react-i18next and bundled, lazy-loaded locale catalogs. Store the system/manual locale preference in the existing local IndexedDB settings store, initialize it after hydration, and keep LINE/user-generated content outside translation.

**Tech Stack:** React, TypeScript, Zustand, IndexedDB, i18next, react-i18next, Vite.

**Spec:** `docs/superpowers/specs/2026-11-03-desktop-i18n-design.md`

## Global Constraints

- Default fallback is Japanese (`ja`).
- Supported locales are `ja`, `en`, `zh-TW`, `zh-CN`, `id`, `ko`, `es`, `fr`, `de`, `pt-BR`, `vi`, and `th`.
- Locale preference stays local and does not alter LINE protocol payloads or user content.
- Language changes preserve the active chat, scroll anchor, and unsent draft.
- Settings backup import remains compatible with old backup files.

## Review Focus

- Missing catalog entries must render the Japanese source string.
- Locale switching during composition must retain the draft and focus.
- Old settings backups without a locale field must still restore.
- Long translated labels must wrap without clipping or changing layout density.
- User names, message bodies, and protocol values must never be translated.
