## 境界別レビュー

### Command execution / child process

- Windows secure store は固定 `powershell.exe` script を `execFile` で実行し、秘密値は child environment 経由。secret をshell文字列へ埋め込む経路は確認されなかった。
- `Vyline/packages/cli/src/index.ts` は `spawnSync(..., { shell: true })` を Windows で使用する。呼び出すcommandは `git` / `bun` / `tar` / `schtasks` 等のローカルCLIで、remote入力から直接command名へ到達する経路は確認されなかった。
- ただし archive/path 等のユーザー入力が引数に入るため、将来は Windows 互換性を確認しつつ shell 非経由化または executable 解決の固定化を推奨する。

### SQL

- iOS backup parser の通常queryは固定SQL + bind parameter。
- `extract.ts` の動的WHEREは `domain LIKE ?` という固定fragmentの反復だけを組み立て、domain値自体はbind parameterへ渡す。SQL injection成立経路は確認されなかった。

### WebSocket / DoS

- upgrade時に LAN subdevice auth、account match、sessionId を確認する。
- attach時にも session/account を再照合する。
- frame size、mic queue、per-call client countを制限した。
- process全体の総 WebSocket 接続数やIP/token単位connection rateは未実装。

### Logging / errors

- Pino `formatters.log` と `hooks.logMethod` の両方で redaction/sanitization を適用する。
- `Error` object は sanitized shape へ変換し、一般APIの5xxは generic response とする。
- debug decrypt sample も生のdecrypt errorを返さず `decrypt failed` のみ返す。
- call session error も WebSocket/API snapshot へ upstream detail を出さず固定文言のみ返す。

### Public API token persistence

- token本体はSHA-256 hashのみ永続化し、account allowlistなしのlegacy tokenはfail-closedに移行する。
- `lastUsedAt` のbackground更新は保存処理を直列化し、一時ファイルから原子的に置換して途中JSONを公開しない。

## CVE / dependency scan

依存関係のCVE確認は `bun audit` と GitHub Actions の OSV/Trivy を使用する。2026-08-31 に Bun v1.4.0 で `bun audit` を実行し、321 packages を確認して既知 vulnerability は 0 件だった。scan結果は実行時点の advisory database に依存するため、「既知CVEが0件」と「脆弱性が存在しない」は同義ではない。

CIには以下が存在する。

- OSV recursive source scan
- Trivy filesystem scan（vuln / misconfig / secret）
- Trivy container image scan

## Remaining risks / unknowns

| Risk | 評価 | 理由 / 次アクション |
| --- | --- | --- |
| Global HTTP body limit が既定2 GiB | Medium | Android backup互換のためglobal縮小は難しい。route-level body limitへ段階的に分離する |
| GitHub Actions がtag参照 | Medium/Low | `actions/checkout@v4` 等をcommit SHA pinし、Dependabot等で更新する |
| Artifact signing / provenanceなし | Medium/Low | checksumに加えSigstore/SLSA provenanceを検討する |
| CLI Windows `shell:true` | Low/Medium local | remote RCE経路は未確認。Windowsでshell:false互換性test後にhardeningする |
| loopback APIをローカル主体から完全認証していない | Medium local | local malware/別user/processは現在のtrust boundary。必要ならlocal session secret/CSRF対策を導入する |
| process全体のWS connection budgetなし | Low/Medium | per-call上限は追加済み。global/IP単位budgetは将来追加 |
| DNS rebinding / outbound egress | Low/Medium | application URL validationに加え、self-host環境ではnetwork egress policyも推奨 |

### 既知の検証制約

`Vyline/packages/protocol/stack` は監査開始前からユーザー作業として大量削除されている。このため通常の `bun test` は `Vyline/packages/protocol/stack/test-preload.ts` の preload で失敗し、Android backup test は `@vyline/protocol/stack` import 解決で実行不能になる。監査ではこの領域を復元/resetせず、独立して動くSecurity testを `bun --config=NUL test ...` で実行した。
