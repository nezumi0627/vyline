# アカウント別のバックアップ容量

最終更新: 2026-08-31

## 概要

各アカウントに10GBずつの保存枠があります。他アカウントの使用量は加算しません。
設定の「詳細・復元」と「ストレージ」で、アカウント別の使用量・残量・内訳を確認できます。

## 実装状況

- 状態: 実装済み（サーバーと画面の両方の更新が必要）
- 対象環境: Bunバックエンド、Desktop/Web、Dockerセルフホスト
- 10GBは10 × 1024³バイトです。

## 事前準備

復元先のアカウントを確認し、AndroidのDB/ZIPやiOSの元バックアップを手元に残してください。
元ファイルは変更しません。上限に達しても既存データを自動削除しません。

## 手順

1. 設定の「詳細・復元」を開き、「アカウント別の保存容量」を確認します。
2. AndroidのDB/ZIPを選択します。読み込みは10GB、復元対象のZIP展開データも10GBまでです。
3. 復元後の履歴・メディア・VylineBackupが、そのアカウントの10GB以内に収まる場合に統合します。
4. 復元やバックアップの作成・削除後は使用量を更新します。「更新」からの再取得も可能です。

使用量の内訳:

- 履歴: SQLiteで使用中のページと現在のWALのバイト数。全メッセージは走査しません。
- メディア: 永続メディア索引でそのアカウントに紐付いた保存済みファイルの合計。
- バックアップ: 正規化SQLiteスナップショットと、任意のメディア付随ディレクトリの合計。

VylineBackupはSQLite形式だけを扱います。旧JSON形式のバックアップは読み込み・一覧・容量集計の対象外です。
メディアはSQLiteへbase64で埋め込まず、ファイルとして逐次コピーします。作成途中のデータは公開一覧へ出ず、
失敗時に削除されます。

共有キャッシュ・認証情報・設定・アップロードの一時ファイルはこの保存量に含みません。
分割アップロード中の一時データには、別途アカウント単位で10GBまでの受付枠があります。
復元・再実行では、重複するメッセージや保存済みメディアを二重追加しません。

## 確認方法

アカウントAが8GB、Bが6GBなら、それぞれ残り2GB、4GBです。
通常の受信や同期を停止する制限ではありません。既存データや通常同期で10GBを超えた場合は、バックアップの作成・復元が拒否されます。閲覧とバックアップの削除は可能です。

## よくある問題

| 症状 | 対処 |
| --- | --- |
| Androidの読み込み上限が2GBと表示される | 古いバックエンドです。ソース変更だけでは稼働中Dockerへ反映されません。サーバーと画面を同じ更新版へ揃えてください。 |
| 10GB未満のZIPでも容量不足になる | ZIPの圧縮サイズと、既存データを含む復元後の保存量は異なります。内訳を確認してください。 |
| 使用量を取得できない | 接続・アカウント権限を確認し、「更新」で再試行してください。失敗を0バイトとして表示することはありません。 |

旧 `VYLINE_ANDROID_BACKUP_MAX_BYTES` / `VYLINE_ANDROID_BACKUP_MAX_EXTRACT_BYTES` による個別上限は使用せず、共通の10GB制限を適用します。
明示的な `VYLINE_MAX_REQUEST_BODY_BYTES` やリバースプロキシの制限は維持します。画面からは小さな分割リクエストで送信します。
