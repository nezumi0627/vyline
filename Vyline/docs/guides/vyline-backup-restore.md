# VylineBackup の保存・復元仕様

VylineBackup は、指定アカウントの chatdb と保存済みメディア参照を JSON スナップショットとして保存します。認証情報や E2EE 秘密鍵は含みません。保存先は `VYLINE_BACKUP_DIR`（未指定時は `backend/data/backups`）です。

## 保持するデータ

- 個人チャット・グループ／ルームチャットを `chatMid` 単位で分離
- メッセージ本文、送信者、時刻、コンテンツメタデータ、関連メッセージ、リアクション、既読 (`seen` / `readCount` / `readBy`)
- 取消し・編集の履歴とソフト削除状態。削除時もレコードと復元用スナップショットは消しません
- `localReadUpTo`、同期時刻、box order などの DB メタデータ
- メディアを選択した場合のみ、メッセージIDに紐づく保存済みバイト列を同梱

## 安全性と互換性

現在のスナップショットは v2 です。JSON 本文（整合性フィールドを除く）の SHA-256 を検証し、別アカウント、壊れたレコード、存在しないメッセージを指すメディア、破損した Base64 は復元対象にしません。作成中の電源断で不完全な本体が残らないよう atomic write を使います。

旧 v1（整合性フィールドと meta がない形式）は読み込み可能です。ただし v1 に存在しない既読カーソルなどは復元できません。

復元は上書きではなく追加マージです。すでにあるメッセージの新しい本文・既読・取消し状態を古いバックアップで巻き戻さず、新規レコードだけを追加します。したがって同じバックアップを複数回復元しても履歴は増殖しません。復元対象をチャット単位で絞り込むこともできます。

## メディアとアカウント分離

メディアの読み書きキーは `accountId + chatMid + messageId` です。別アカウントのバックアップで上書きすることはありません。メディアが欠損していても、メッセージ本体の復元は継続します。

Desktop のプロフィールキャッシュもアカウント別ファイルへ保存されます。複数アカウントを扱う場合、別アカウントの復元順序によってプロフィール情報が混ざらないようにしています。

## SQLite について

通常の chatdb 正本はアカウント別の `data/accounts/<safe-id>/chatdb.sqlite` です。SQLite の WAL、トランザクション、次のインデックスを使います。

- `(chat_mid, created_time DESC, id DESC)` — 履歴ページング
- `(chat_mid, is_deleted, created_time DESC, id DESC)` — 通常表示と復元一覧の分離
- `(chat_mid, message_state)` — 取消し・復元状態の検索

既存の `chatdb.json` / `chatdb-<account>.json` は初回起動時に読み込み、SQLite へ移行します。旧ファイルは削除しません。バックアップの交換形式は引き続き JSON v2 とし、SQLite の内部ファイルを直接コピーせず、整合性ハッシュ付きスナップショットを使ってください。

削除は `isDeleted` と `deletedAt` を立てるだけで、行・本文・履歴・既読情報は保持します。通常取得では除外し、復元操作だけがフラグを解除します。サーバーから同じメッセージが再同期されても、ローカルの削除状態は復活しません。
