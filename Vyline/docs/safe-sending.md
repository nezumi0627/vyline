# 安全なメッセージ送信

Vylineの送信処理は、通信の成否を確認できないときに同じメッセージを自動再送しません。応答が失われても、LINE側では送信が完了している場合があるためです。

## 送信結果の扱い

| 状態 | 意味 | Vylineの動作 |
|---|---|---|
| 送信済み | LINEから成功応答を受け取った | ローカル履歴へ反映し、差分同期を予約 |
| 結果不明 | タイムアウト・通信切断・サーバーエラーで成功応答を確認できない | 履歴を更新して照合。見つからない場合も、自動再送しない |
| 拒否 | 入力・権限・相手の状態など、4xx応答で拒否された | 再送ボタンを出さず、内容や状態の見直しを案内 |
| 送信制限 | ABUSE_BLOCKまたはレート制限を示す応答 | その操作を停止。回避・ローテーション・自動再試行をしない |

結果不明のメッセージを再送するときは、まず履歴を更新します。履歴で確認できず、再送可能なメッセージの場合に限り、重複して届く可能性を警告して利用者に選択を求めます。

## 技術的な保護

- アカウントごとに送信RPCを直列化し、共有接続上の同時送信を避けます。
- E2EEの鍵再取得・ローテーションは、判定可能な鍵エラーに限って行います。
- 暗号化に関する失敗を、暗号化なしの送信へ安易に切り替えません。
- 送信先がブロック済みの友だちなら、クライアントとバックエンドの両方で送信を止めます。
- レート制限やアカウント制限を回避するための動作は実装しません。

## テスト

送信テストを実施する場合は、ユーザーが指定した「うがうがうー」と「Clock Angle」のみを対象にします。それ以外の実アカウントやグループへテスト送信しません。自動テストはHTTP/RPCをモックし、LINEへ送信しない形で行います。
