# Vyline 設定・Beta機能の再編

## 目的

設定を目的別に整理し、文字倍率がパネルや余白を拡大しないようにする。実装済みのBeta機能は制約と失敗時の動作を確認してから本番導線へ移し、不要な一括ブロック確認はBetaから削除する。

## 情報設計

| 順 | セクション | 主な内容 |
|---|---|---|
| 1 | プロフィール | LINEの名前、アイコン、プロフィール背景 |
| 2 | トーク | 既読、表示、トーク背景、文字サイズ、メディア自動保存 |
| 3 | テーマ | NezuThemeのプリセット、色、トーク背景画像 |
| 4 | 通知 | LINEの通知設定とVylineのPC通知を別々に表示 |
| 5 | プライバシーとブロック | 配信者モードの伏せ方、ブロックリスト、プロキシ |
| 6 | デバイスと容量 | サブデバイス、ストレージ |
| 7 | バックアップと復元 | VylineBackup、LINE Desktop取込、iTunes／Apple Devices復元 |
| 8 | サポートと詳細 | 同期、診断情報、設定の復元・初期化 |
| 9 | ベータ機能 | 実験機能のみ。既存の本番機能のオン・オフは置かない |
| 10 | INFO | バージョン、作者、GitHub、X、Discord、ライセンス |

ブロック確認は相手のプロフィール操作、MID検索は友だち追加画面の操作とする。プロフィールのブロック確認を設定トグルで隠さない。

## 機能の移動と境界

| 機能 | 方針 |
|---|---|
| プロフィールでブロック状態を確認 | 本番化し、相手プロフィールから明示操作で実行 |
| 友だち全員の自動ブロック確認 | Beta UIと定期実行を廃止。個別確認のAPIは他の機能のために必要なら維持 |
| MIDプロフィール確認 | 友だち追加画面に移す。MIDから追加前にプロフィールを表示し、友だち追加は別操作にする |
| Agent I | Betaフラグ依存を外し、トーク内の明示操作と専用設定に移す。Yahoo送信の同意と送信範囲を維持 |
| iTunes／Apple Devices復元 | Betaからバックアップと復元へ移す。既存の検出・プレビュー・選択を維持 |
| PC通知 | ブラウザ通知権限、Vyline設定、OS側拒否を別状態として表示。通知本文の伏せ方を提供 |
| ブロックリスト | アカウント別SQLiteキャッシュを正本にして差分同期。LINEから取得した集合との差分のみ更新 |
| 自分をブロックしている人 | 表示しない。LINEから直接確認できる確定情報がないため、推定一覧も提供しない |
| メディア自動保存 | 設定可能にし、初期値はON。OFFでは明示的な保存操作だけを行う |
| 診断情報 | 生ログ閲覧を主導線にせず、利用者が内容を確認してから保存・共有できる診断パッケージにする。自動送信しない |
| Desktopデータ取込 | 「LINE Desktopからデータを取り込む」と表示し、元データの場所・読取専用・取り込み結果を明記 |
| VylineBackup | 選択チャットとメディアの実測可能なメタデータから概算サイズを表示し、未取得分を概算と明示 |
| INFO | 「情報」ではなく「INFO」。OpenCode Goリンクを削除し、重複リンクをなくす |

## UI・文字サイズ

- NezuThemeの色・背景は利用者のテーマ設定を尊重し、設定画面に別の色体系を持ち込まない。
- 設定ナビは目的ごとにグループ化し、項目間の余白を増やす。NezuThemeのプリセットとカスタム値を分け、色設定を過密な一覧に詰めない。
- `fontScale` はhtmlのroot font-sizeに適用しない。メッセージ本文、入力欄、チャット一覧のプレビューなど文字要素だけを倍率対象とする。
- チャット背景画像はユーザー指定画像を選択・解除でき、トークプレビューと実チャットの両方で確認する。
- プライバシーの初期マスク範囲は、表示名・アイコン・URL・MID・ステータス。配信者モード自体は既存のOFF状態を維持し、ON時に範囲を個別変更できる。

## 実装順と受け入れ条件

1. UI分類・文字サイズ・テーマ余白・INFOを整理する。倍率変更でナビ幅、ボタン高、カード寸法が変わらないこと。
2. 既存Beta機能を本番UIへ移す。フラグを外しても旧保存設定が壊れず、APIエラーと権限状態を表示すること。
3. ブラウザ通知・詳細な配信者モード・メディア自動保存を実装する。許可拒否、権限未決定、オフラインを区別すること。
4. ブロックリストSQLite差分同期、Betaの推定一覧、バックアップ容量概算を実装する。アカウント分離、失敗時の既存値保持、過剰なLINE RPCがないこと。
5. ヘルプ・診断とDesktop/iTunes復元導線を整理する。診断は利用者の明示操作なしに外部送信しないこと。
6. 各機能のユニットテスト、型チェック、lint、build、既存テストを実行し、実画面を確認する。

## 未確定・安全境界

- LINEが提供しない「相手が自分をブロックした」という直接証拠は表示しない。検証APIの結果は推定として扱い、個別の照会を低頻度に制限する。
- ブラウザ通知はアプリが動作中のページから発火する。Service WorkerやPush購読が現行構成にない場合、ブラウザ終了後の通知を約束しない。
- DBスキーマ追加は既存ブロックリストを残す段階移行とし、SQLiteが使えない場合は既存API結果で継続する。
- バックアップ容量は、選択範囲・メディア実データの有無を反映した概算とし、作成前に確定サイズとして表示しない。
