# Vyline 機能拡張計画

## 方針

要求を安全性の高い基盤から縦割りで実装する。LINE.js / Vyline-search に存在する証拠を確認できない操作は、推測でAPIを追加せず「未対応」として分離する。認証情報・実アカウントへの送信・危険チャットの操作は検証対象外とする。

## タスク

### Phase 1: 事故防止

- [ ] チャットロックをチャット一覧の右クリックから設定
- [ ] API側で送信、取り消し、名前変更、退出、ブロック等の対象操作を一括拒否
- [ ] GUI側で入力・操作メニューを無効化し、ロック状態を表示
- [ ] ロックの永続化と回帰テスト

### Phase 2: 設定整理

- [ ] 情報を設定一覧の最下部へ固定
- [ ] iTunes / Apple Devices 復元を詳細・復元へ移動
- [ ] 既読無効化一覧とブロック一覧を専用タブで表示・解除

### Phase 3: 表示・通知・送信

- [ ] 動画の独自再生ボタンを除去し、標準 video controls を使用
- [ ] POSTNOTIFICATION の受信形式を調査し、実データを表示
- [ ] 連続画像のグルーピング条件と表示仕様を確定・テスト
- [ ] LINE.js / Vyline-search の送信経路を現行プロトコルと比較

### Phase 4: アルバム・ノート

- [ ] 個人/グループのアルバム操作を対応表へ追加
- [ ] ノート操作の不足分を対応表へ追加
- [ ] 根拠が確認できたものだけ stack → domain → BFF → GUI へ実装

## チェックポイント

- Phase 1 完了時: ロック中チャットでGUI/APIの危険操作が全て拒否される
- Phase 2 完了時: 設定導線が整理され、既存の復元機能が壊れていない
- Phase 3/4 完了時: 実送信なしのデモ・モックテストと型/Lint/buildが通る

## リスク

| リスク | 対策 |
|---|---|
| LINE APIに未確認の操作がある | RPC_DICTIONARY / LINE.js / Vyline-searchの証拠を必須化 |
| ロック漏れで送信事故が起きる | GUIではなくAPIサービス層を最終防衛線にする |
| 画像グループ化で既存表示が変わる | 送信・受信・異なる投稿者・時間差を個別に回帰テスト |
