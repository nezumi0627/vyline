# nezu-md Compliance Checklist

公開前、または PR レビュー時に使う。

---

## Meta

| Field | Value |
| --- | --- |
| Document | |
| Author | |
| Date | |
| Target Level | L1 / L2 / L3 / L4 |
| Result | Pass / Fail |

---

## L1 — Structured

- [ ] `H1` が 1 つだけある
- [ ] Information Hierarchy（What → Why → How → Structure → Future）に沿っている
- [ ] Hero または同等の導入がある
- [ ] Summary がある
- [ ] Features がある
- [ ] Quick Start または同等の利用手順がある
- [ ] License が明示されている

## L2 — Visual

- [ ] バッジまたは Status 表示がある
- [ ] 比較・対応・機能一覧に表を使っている
- [ ] 長文の壁がない（段落が適度に分割されている）
- [ ] コードブロックに言語指定がある
- [ ] 必要なら Mermaid / ツリー / 画像領域がある

## L3 — Product

- [ ] Hero だけでプロジェクトの正体が分かる
- [ ] Quick Start がコピーして最短成功できる
- [ ] Architecture または Directory Structure がある
- [ ] FAQ が想定誤解を解消している
- [ ] Roadmap または Status で現状と将来が分離されている
- [ ] 空洞セクション（見出しだけの節）が無い
- [ ] 曖昧語（いろいろ、適切に、など）が残っていない

## L4 — Reference

- [ ] 仕様・原則・チェックリストが相互リンクされている
- [ ] テンプレートがある
- [ ] 実例がある
- [ ] AI 向け手順（Skill）がある
- [ ] バージョン方針がある

---

## Content Quality

- [ ] 見出しが内容を予測させる
- [ ] 主張が具体的で検証可能
- [ ] 手順とリポジトリ実態が一致する
- [ ] 外部リンクが死んでいない（確認時点）
- [ ] 用語が文書内で一貫している

## GitHub Rendering

- [ ] GitHub preview で崩れない
- [ ] 相対リンクが正しい
- [ ] 画像パスが正しい（使う場合）
- [ ] 目次が必要な長さなら用意されている
